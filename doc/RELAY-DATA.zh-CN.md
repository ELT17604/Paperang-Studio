# 中转数据存储与保留

[English](RELAY-DATA.md) · [远程打印](REMOTE-PRINTING.zh-CN.md)

## 服务器在线数据

配置中的 database 指向一个 SQLite 数据库。默认安装器使用
`/var/lib/paperang-relay/relay.sqlite3`；home 集中部署可放在专用 data/ 目录。
WAL/SHM 如存在，会在数据库旁边。主文件权限为服务账户的 0600。

| 表 | 内容 | 保留与清理 |
|---|---|---|
| jobs | 正文、发送者/IP/浏览器元数据、长短 ID、状态、时间、分区计数、收据/认领哈希及密钥 ID | 默认从 updated 起 7 天，活动 claimed/printing 除外 |
| keys | 密钥 ID、名称、权限、设备、token 哈希及吊销状态 | 无自动过期；吊销使其失效，删除才移除记录 |
| usage | IP 对应 UTC 固定小时的条数/字符计数 | 清理早于此前 48 个小时窗口的记录 |
| devices | 每个设备最后一次状态/遥测和心跳时间 | 后续回报覆盖，无按时间删除行的策略 |

`GET /v1/public/status` 的 policy.retention_days 返回实际配置值。
设备超过 15 秒没心跳会显示离线，但不会因此删除遥测记录。

清理由投稿、设备回报/列表轮询、任务查询等请求触发，不是独立定时器。
完全无人访问时，过期记录可能继续存在，直到下次清理。queued 和终态记录按
最后更新时间过期；claimed/printing 超过 5 分钟无更新先改为 unknown，
并刷新 updated，再从此时开始终态保留窗口。人工确认出纸也会刷新 updated。
普通查看任务不会延长保留期。

SQLite DELETE 是逻辑删除，不保证对磁盘、快照做取证级擦除，文件也未必立即缩小。
应使用 SQLite backup API，或停服务后复制整个状态目录；运行时不能只复制主文件
而忽略 WAL。

## 浏览器收据

当前标签页的 sessionStorage 保存最近一次跟踪状态及最多 20 个原始收据，
不保存正文、访客元数据或访问 token。刷新页面通常可恢复，关闭标签页通常结束
该存储会话，但浏览器恢复会话的行为可能不同。这不是永久归档或账号历史。

服务器只保存收据哈希。匿名投稿者丢失原始收据后，不能仅凭公开 12 位 ID
找回私有正文；管理员或所属设备仍可通过有效权限读取尚未过期的任务。

## 原始密钥、备份及日志

标准安装器会另存 root 可读的 initial-credentials.jsonl，恢复工具也可能导出
替代密钥。它们是明文原始凭据，与数据库中的哈希不同，没有自动过期清理。

备份是独立副本，不受在线任务 7 天规则影响。基础安装器不安排定时备份，也不
自动删除备份；自行部署的维护脚本需另设备份保留策略。恢复旧快照会恢复当时的
任务和密钥状态，可能使快照之后才被吊销的密钥再次有效。

应用/Nginx 日志不等于任务历史，其位置和轮转取决于部署。共享 systemd/Cloudflare
日志和外部快照不属于数据库清理范围。
