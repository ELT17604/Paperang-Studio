# v0.3.1 所有者私钥切换与故障修复

本版修正三个问题：匿名浏览器可查看本身份任务的状态和分包进度，但其他身份任务返回 404，所有普通查询仍不含正文、图片和投递 metadata；活动打印 payload 恢复 IP/UA/语言等明确渲染字段；WinLite 默认使用配对的 RSA 所有者文件，后台与 C 管理共用已证明的公钥身份。

M 设备执行密钥返回 403 管理拒绝属于权限隔离本身，不应把 M 升级成无限管理权限或尝试从它反查 C 秘密。诊断可在本机请求 GET /v2/auth/me 确认 role；A/B/M 无权管理，旧秘密也不能从摘要恢复。

## 默认连接方式

WinLite 的连接页选择“所有者私钥文件”，不再要求把 M 密钥粘贴进管理页。文件包含服务器根地址、服务器已登记的 credential id 和本地 RSA 私钥；公钥先登记，再通过一次性 RSA-PSS/SHA-256 挑战证明持有权。WinLite 每约九分钟刷新十分钟短会话，不把会话 token 写入配置。所有鉴权请求携带原生客户端标记，兼容服务器的安全 Cookie 修正。私钥保留在当前用户 ACL 保护的本机目录，服务器只接收公钥和签名。

C 的普通 bearer/口令仍不能作为设备执行凭据；只有已证明的 publickey C 会话可进入执行接口，仍限定其设备和活动 claim。其他平台的 M 执行合同保留，不代表 WinLite 默认开放旧 token 连接。显式 A 投稿密钥仍为投件箱；匿名浏览器是只读本身份状态的特例。

## 安全切换顺序

1. 本机生成新 RSA 3072/4096 密钥和唯一 credential id，保存私钥到受限目录；只将公钥给服务器。
2. Linux 操作员使用固定提交和校验和运行 Server/upgrade_owner.py。工具先在临时副本运行测试，备份代码/配置/数据库，拒绝活动 claimed/printing 任务；新服务暂时暂停认领，并登记待证明公钥。
3. Windows 验证新的公钥证明、C 管理接口及设备执行接口。等待旧客户端待回报记录清空，退出旧客户端。
4. 新所有者调用 POST /v2/admin/security/retire-others，明确 confirm=true、keep=当前 id。服务器拒绝正在打印的切换，保留新所有者，吊销所有其他既有凭证/会话并写入审计。不能用普通 C bearer 或未证明公钥调用。
5. 操作员工具观测到证明与退役审计后恢复认领，重新启动服务，并删除数据/配置/源码目录中已知的旧凭证导出文件。旧密钥已失效；未知位置的人工备份不被假装已删除。
6. WinLite --configure-owner <文件> 先验证 C 与执行权限，之后才重新加密保存配置。DeviceKey 清空，保留打印机、模板和打印偏好；重新启用托盘和既有自启设置。

任何步骤失败，不提前吊销旧管理员，不移除唯一可用私钥。新代码启动失败会恢复原代码和配置；数据库不自动回滚，以免丢弃新投稿或恢复已吊销的密钥。备份由操作员私下保管，不上传 Git。工具等候十五分钟仍未证明/退役时保持暂停，并报告恢复位置。
