# Paperang Studio v0.3.2 API v2 contract

Paperang Studio provides a Mac loopback HTTP API and a Relay HTTP API. Both use v2. Content, templates and saved settings use schema 1. P2 framing and database migrations have their own versioning.

## Mac loopback API

The machine-readable normative route/request/response definitions are [openapi.json](openapi.json). [API.md](API.md) and [API.zh-CN.md](API.zh-CN.md) describe examples and consent. Bind only 127.0.0.1. Every business request needs the local Bearer secret, allowed Host and optional allowlisted Origin. This token grants local device control; Relay A/B/C/M identities do not authorize this surface. CORS preflight requires an allowed Origin. Do not expose this service publicly.

All previously implemented local resources move to `/v2`: status, devices, protocol, settings, jobs, logs, openapi, scan, connect, disconnect, query, render, feed, job lookup and cancellation. HTTP methods and request shapes are retained; text and imageBase64 remain mutually exclusive. No shell or terminal-input endpoint is added. HTTP errors remain `{ "error": { "code": "...", "message": "..." } }`.

After Host/Origin/authentication and rate checks, `/v1` and `/v1/*` return 410 with code `api_v1_retired`, for GET/POST/OPTIONS, before JSON parsing or content-type checks. Invalid authorization still returns 403, malformed HTTP 400, throttling 429. No old request executes business logic or is translated. Unknown non-v1 routes return 404. No v1 runtime adapter remains. Saved user configuration keys and schema 1 remain supported.

A successful print submission returns HTTP 202 `{id,state:"accepted",note}`; it does not queue behind another job. GET job state is stable English `printing`, `sent`, `unknown`, or `cancelled`, with display-only `stateLabel` and `physicalCompletion:"unknown"`. Local jobs are the latest 30 in this session; restart clears them. `sent` means transport completed, never paper verification. Local API does not implement manual paper confirmation or content extraction from Relay history. Cancellation only stops later transmission and disconnects; buffered bytes cannot be recalled. A 12-second connection deadline can end an HTTP response without cancelling a started print. Poll existing ID; never automatically resubmit an uncertain print. The local API has no Relay request-id deduplication guarantee.

Limits remain 2 MiB body, 16 KiB headers, 8 connections, 20 authenticated requests/second. No new density/feed/raster/CRC/BLE behavior is introduced.

## Relay API

The existing [AUTH-v2.md](AUTH-v2.md), [api_v2.py](../Server/api_v2.py), and [relay.py](../Server/relay.py) define Relay v2 routes, JSON, errors and authorization; v0.3.2 introduces no Relay wire changes. Relay error JSON is `{error: string, ...optional details}`; local error objects are intentionally separate.

Public status is acceptance/capabilities, not physical printer status. A submits without status access; anonymous and B read their own status; C manages identities/credentials/quotas/history and manually confirms paper; M or proven device-scoped owner C claims active payload and reports execution. Claim secrets gate content; job IDs confer no authority. UUID `request_id` deduplicates within retained history. Job states remain queued/claimed/printing/sent/confirmed/unknown/rejected. Only C paper inspection can establish confirmed; timeouts and report recovery never authorize reprinting. Native C proof sessions expire after ten minutes; active claim windows and retention follow the existing Relay implementation.

## Upgrading from v1

The v0.3.2 release retired Mac Local HTTP v1. Update local callers to v2 paths and stable job states. [Versioning](VERSIONING.md)
