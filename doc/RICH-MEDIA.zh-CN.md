## 已实现的功能

网页 Content → Drawing 可使用手指、触控笔或鼠标绘图，支持笔宽、画布高度、最近 10 笔撤销、清空和可选文字说明。画布为白底，发送时转换成 576 点宽黑白点阵，通过现有任务、鉴权、配额、短 ID、回执和确认流程提交。发送期间冻结编辑控件，避免发送内容与画面变化混淆。页面刷新/关闭不保存绘图草稿；任务回执仍按原有标签页会话保存。这是点阵绘图工具，暂未加入照片上传、矢量编辑或混合文档编辑。

必须同时更新服务端和 App。新客户端声明请求头 `X-Paperang-Content-Types: text,raster1`，旧客户端只能列出文字任务，也不能认领图片。服务器 `/v1/public/status` 的 capabilities 返回 contentTypes/contentSchemaVersion；旧服务端缺少能力声明时网页禁用绘图。

Mac 列表仅下载摘要，选中/打印时读取完整数据，校验宽高、字节数和 SHA-256，预览与实际发送共用点阵。内置样式中图像保持原始 576 点宽，末尾附加本地勾选的正文/身份/时间等字段。自定义模板中图片随正文区块边距等比适配，使用黑白最近邻采样；边距为 0 时原点阵不变。浓度、送纸由本地控制。文字和图片共用自定义模板：正文区块先显示图片，再显示可选说明；标题、身份、时间、编号等仍按模板顺序、字体和留白显示。图像加页脚总高度不得超过 1400 行，超出时应降低画布高度或关闭页脚字段。复制到工作台会复制合成后的图像与页脚，继续使用本地图片调整功能。

## 内容协议

仍使用 POST `/v1/jobs`，旧请求 `{"text":"hello"}` 保持兼容。图片在 text（可空）旁增加 content：

```json
{
  "text": "可选说明",
  "content": {
    "schemaVersion": 1,
    "type": "raster1",
    "width": 576,
    "height": 384,
    "encoding": "base64",
    "bitOrder": "msb-first",
    "blackIsOne": true,
    "data": "恰好72×height字节的Base64编码",
    "sha256": "可选：解码后字节的SHA-256小写十六进制"
  }
}
```

从上到下逐行，每行 72 字节；每字节高位在左，1 黑、0 白。高度为 1–1400 的整数，并受调用者额度限制。浏览器白底合成、阈值 128 二值化；有 Web Crypto 时计算摘要，没有时服务端补算；提供错误摘要会拒绝。Mac 始终校验服务端提供的摘要。不接受未知版本/类型、可执行标记、外部图片 URL 或打印机原始命令。

配额单位为“文字字符数 + 点阵行数”，同时计入单条 `*_max_length` 与每小时 `*_hourly_chars`，原有每小时 IP 条数上限继续生效。例如匿名默认 500 单位，可发送 384 行绘图加最多 116 字说明。只发图也会扣额度，不能绕过纸长限制。原有安装参数继续可用，无额外媒体开关；网页显示用量并在超限时禁用提交。

只有 POST `/v1/jobs` 请求上限扩大至 160 KiB（163840 字节），其他接口仍为 64 KiB。最大原始图像 100800 字节，Base64 134400 字符；反向代理应允许至少 160 KiB 请求。当前小图采用单次受限 JSON 提交，避免先上传后提交的孤立附件。Base64 有约 33% 编码开销，但黑白点阵本身仅为 RGB 的 1/24；576×384 原始点阵仅 27648 字节。

SQLite 以 payload BLOB 存二进制，content_meta 存摘要；列表查询和返回均不带图像字节，设置 truncated:true，完整设备详情/授权短 ID 查询才附带 Base64。公开短 ID 与仅状态回执接口只返回内容类型。图片继承正文的访问控制、保留期、备份和删除规则。旧数据库自动迁移，不改变既有任务。

## 状态修复

新投稿在发送开始和成功接收时都会使旧查询失效；过期的查询/轮询响应不能覆盖新任务和回执。投稿期间禁用查询控件。服务端用 lastStage 保存认领/发送阶段，超时转 unknown 后仍保留。旧任务缺少记录时显示“已接受”并明确结果不确定，不再回到“排队”。数据发送完毕与人工确认纸面完成保持分离。

## 后续扩展建议（尚未实现）

- 手机照片：在网页增加缩放、裁切、灰度和抖动，继续发送同一种 raster1，打印端无需新协议。
- 可编辑绘图：单独保留笔画矢量，打印仍以明确预览后的点阵为准。
- 图文混排：新增版本化 document 类型、顺序区块与客户端合成器，并做能力协商；不能把未知类型当文字打印。
- 大型原图：单独做鉴权附件上传，检查大小、MIME、尺寸、摘要、所有权与过期时间，任务仅引用附件 ID。客户端不直接获取用户提供的 URL。自动重试前先加入幂等机制。

## 验证范围

验证包括查询与投稿竞争、unknown 阶段、精确位序/行序/摘要、服务端尺寸/编码/摘要拒绝、行数配额、旧客户端隔离、数据库迁移和隐私，以及真实 HTTP 最大高度请求。真实浏览器绘图已提交并入队。原生验证包括完整数据获取、像素保持和摘要错误拒绝。本次未重新耗纸，也未在实体手机上测试触摸操作。

网页查询/轮询设置 `X-Paperang-Content-Summary: 1`，保留有权限的说明和图片元数据，但省略 Base64；需要完整图片的私有 API 调用方不设置该头。避免每 250 ms 刷新进度都重新下载图片。
